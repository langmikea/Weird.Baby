Attachments — the same three, named three ways

Throwaway. Nothing here is in the repo and nothing ships. The type, colours, spacing, thumbnail size and the glyph are the museum’s own, copied out of RecordAttachments.jsx and the Record stylesheet. Only the name and the small line under it change between the three columns — the rows, the pictures, the order and the printed text are identical, so what you are comparing is the naming and nothing else. No Record entry has ever carried an attachment, so none of this has ever been on the wall.

What the file is actually called. Nothing is invented and nothing needs writing — and it reads like a directory listing.

The house already leans one way, and it is written into the renderer: attachmentsOf() takes p.label || fileNameOf(p.img) — “the label if it has one; otherwise the file’s own name, which is a fact rather than a caption Ops made up for the row.” That is column 3 when a label exists and column 1 when it does not. Column 2 does not appear in the code at all.
