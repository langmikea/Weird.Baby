## 1. Definition of "comprehensive coverage"

**The phrase is undefined in the repo.** A full search of `BACKLOG.md`, `CLAUDE.md`, `NAVIGATION.md`, `STATE.md`, `DATA_ARCHITECTURE_SPEC_v2.1-target.md`, the decision briefs, and all `docs/` returns **zero** literal occurrences of "comprehensive coverage." The term comes from the kickoff/handoff, not from any committed spec. Per CLAUDE.md §7 ("kickoff anchors can be stale; the codebase is ground truth"), it is flagged here rather than assumed.

The nearest committed anchors that bound the intent:

- **Exhibit-badge completeness.** The 2026-05-25 backfill (`docs/EXHIBIT_BACKFILL_DEPLOY_RUN_REPORT`) drove "Released artifacts with no exhibit badge: **0**" — i.e. *every released artifact carries `exhibit:hunter_root` so nothing is silently dropped from the export.*
- **§3.5 reserved namespaces** (`DATA_ARCHITECTURE_SPEC_v2.1-target.md:220`) — `content_kind` is the media-variant taxonomy (`official/live/lyrics/cover`); `exhibit`, `scope`, `author` are structural.
- **The HEIC incident / broken-preview work** (CLAUDE.md session log 2026-05-30) — *assets that fail by path OR format must not render as silent blankness.* This makes "every released artifact has a renderable asset signal" a coverage dimension.
- **§12.6/§12.7** — released artifacts render with correct pill tiers and no crash.

### Proposed working definition (flagged for operator sign-off)

> **An exhibit has comprehensive coverage when every released artifact badged into it is complete and correctly renderable:**
> **(A) Structural** — carries `exhibit:hunter_root` so it exports (no released-but-unbadged drop-outs).
> **(B) Identity/metadata** — `title`, `source_url`, `source_platform`, `post_date`, `media_type` are present and non-empty.
> **(C) Renderable asset** — has an asset signal appropriate to its `media_type` (a `thumbnail_url`/`primary_url`, or at minimum a clickable `source_url`) so it never renders blank — the HEIC lesson.
> **(D) Variant tagging** — `content_kind` is set wherever the media-variant taxonomy applies.
> **(E) Integrity** — no orphaned references, no duplicate cards, no records that should not be released.

Dimension **(D)**'s scope is genuinely ambiguous and needs an operator ruling — see §3, G5. The rest are mechanically checkable and measured below.

**G3 — Missing `post_date` (16).** `MV-HR-20260405-029`; `MV-HR-20260417-001/003/005/007/009/011/013/015/017/019/021/023` (13 ReverbNation audio tracks); `MV-20260419-003/004`; `MV-HR-20260421-001`. Low severity — metadata completeness only.

All but `-029` carry a clickable `source_url`, so they degrade gracefully via the 2026-05-30 broken-preview fallback. The HEIC-incident class; largely cosmetic now that the fallback shipped.

**G5 — `content_kind` asymmetry (24) — NEEDS DEFINITION RULING.** All 39 valid `content_kind` tags sit on `link` (YouTube) artifacts. **G6 — Off-spec `content_kind` value (1).** `MV-20260529-001` (gallery container) carries `content_kind:other`, not in the `official/live/lyrics/cover` set. The front-end already ignores off-spec values (CLAUDE.md 2026-05-30), so it is harmless today; flagged for cleanliness.

**Referential integrity (not a gap):** the gallery container `MV-20260529-001` has `cover_artifact_id: MV-HR-20260405-017`, which is **not** a top-level record but **is** one of the container's 11 embedded `gallery[]` children — resolves correctly within the container.
